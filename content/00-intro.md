# 00. 학습 로드맵과 이 문서의 사용법

> **목표:** 팀원 A가 공격 시스템을, B가 체력 시스템을, C가 UI를 만들더라도 각자가 상대 코드의 내부 구현을 몰라도 연결·테스트·병합할 수 있는 구조를 설계한다.

이 문서는 기술 키워드만 소개하지 않는다. **왜 필요한가 → 문법과 실행 범위 → 어떤 파일의 어떤 코드인가 → 실행 순서 → 결과 확인 → 실패 사례** 순서로 학습한다. 모든 핵심 사례는 같은 **공격 → 체력 감소 → UI 갱신** 시나리오를 사용한다.

## 1. 두 종류의 결과물

| 경로 | 용도 | 실행 방식 |
| --- | --- | --- |
| `docs/` | GitHub Pages가 공개하는 완성된 HTML | 브라우저에서 `docs/index.html` 열기 |
| `content/` | 문서 원본 Markdown | 수정 후 `python scripts/build_site.py` |
| `unity-example/Assets/_Game/` | 실제 C# 스크립트와 `.asmdef` | 새 Unity 6 프로젝트의 `Assets/`에 복사 |
| `.github/` | 코드 리뷰 템플릿 및 작업 예시 | GitHub 저장소에 업로드 |

## 2. 실제 실습 환경

- **Unity:** Unity 6 계열에서 새 3D Core 프로젝트를 만든다. 기존 프로젝트에 바로 넣지 않는다.
- **C#:** Unity가 제공하는 C# 언어 버전을 기준으로 한다. 따라서 교육 코드에서는 최신 C# 전용 문법에 의존하지 않는다.
- **테스트:** Unity Test Framework / NUnit을 사용한다. 패키지가 없다면 Package Manager에서 설치한다.
- **버전 관리:** Git과 GitHub를 사용하지만, 구조 설계 원칙은 UVCS에도 적용된다.
- **배포:** GitHub Pages의 `main` 브랜치 `/docs`를 사용한다. 별도 Node.js 빌드가 필요 없다.

## 3. 이 책의 큰 흐름

1. **기초**: 변수·객체·타입·범위·참조를 분리해 이해한다.
2. **연결 계약**: Interface, Delegate, Event, DTO로 무엇을 주고받을지 명시한다.
3. **의존성 조립**: DI, Adapter, Facade로 기존·신규 코드를 연결한다.
4. **프로젝트 경계**: Namespace, 접근 제한자, Assembly Definition으로 참조 규칙을 만든다.
5. **Unity 특성**: ScriptableObject, `[SerializeField]`, `[RequireComponent]`, 생명주기와 프리팹 연결을 다룬다.
6. **협업 완성**: 단위/통합 테스트, Git/PR/CI, 실제 실습으로 종료한다.

## 4. 학습 중 자주 하는 오해

| 오해 | 정확한 설명 |
| --- | --- |
| 인터페이스가 객체를 만들어 준다 | 인터페이스는 타입 계약이다. 객체는 구현 클래스에서 생성한다. |
| Event는 전역 변수다 | Event는 특정 **객체 또는 타입**에 속한다. `static`인지 여부에 따라 소유 범위가 달라진다. |
| `using`은 DLL을 불러온다 | `using`은 주로 네임스페이스 이름 해석을 돕는다. 어셈블리 참조는 별도 설정이다. |
| `.asmdef`가 GameObject를 연결한다 | `.asmdef`는 컴파일 시 타입 접근 관계를 설정한다. 실제 게임 오브젝트 연결은 별도로 해야 한다. |
| Git 충돌이 없으면 통합이 끝났다 | 코드 컴파일, 런타임 참조, 이벤트 시점, 씬 구성까지 확인해야 한다. |

## 5. 표기를 읽는 법

이 문서에서는 코드마다 **실제 파일 경로**, **선언 주체**, **상태 소유자**, **접근 가능 범위**를 구분한다. 예를 들어 `private int hp`는 클래스 인스턴스마다 별도의 필드다. `static int count`는 같은 타입의 인스턴스가 공유하는 필드다. `int amount`가 메서드 인자라면 매개변수고, 메서드 내부 `int next`는 지역 변수다. **C#에는 C/C++처럼 네임스페이스 바로 아래 선언하는 전역 변수가 없다.**

## 6. 첫 실습: 10분 경로

1. 새 Unity 프로젝트를 만든다.
2. 이 저장소의 `unity-example/Assets/_Game/`을 Unity 프로젝트의 `Assets/_Game/`에 복사한다.
3. Unity 메뉴 `Tools > Collaboration Lab > Create Demo Scene`을 실행한다.
4. 생성된 씬에서 Play 후 `Attack enemy` 버튼을 클릭한다.
5. HP가 100에서 85로 변하는지 확인한다.
6. EditMode와 PlayMode 테스트를 실행한다.

실습에 실패했다면 [15. 오류 해결](15-troubleshooting.html)을 먼저 확인하자. 코드가 이미 제공되므로 한 번에 모두 작성하기보다는 **코드를 읽고 주석을 바꾸며 다시 실행**하는 편이 학습에 유리하다.
