# 15. 오류 해결·선택 기준·팀 체크리스트

## 1. 먼저 어떤 종류의 실패인지 분류한다

| 증상 | 먼저 확인할 것 | 가능한 원인 |
| --- | --- | --- |
| `CS0246` 타입을 찾지 못함 | `using`, namespace, `.asmdef` References | 컴파일 의존성 누락 |
| `CS0122` 접근할 수 없음 | `public/internal/private` | 접근 제한자 불일치 |
| `CS0012` 어셈블리 참조 필요 | `.asmdef` References | 다른 어셈블리 의존 누락 |
| `NullReferenceException` | Inspector 필드 / 생성자 DI | 객체 참조 미연결 |
| HP는 감소하지만 UI가 안 변함 | 이벤트 발행/구독/해제/Bind | 런타임 통합 문제 |
| Test Runner에서 테스트가 안 보임 | Test Framework 설치, test asmdef | 테스트 어셈블리 인식 실패 |
| Git 충돌 없음, 게임은 작동 안 함 | 데이터 소유자/API/씬 설정 | 구조적 통합 실패 |
| 플레이 재시작 후 중복 콜백 | `static event`, 구독 해제 | 생명주기·정적 상태 문제 |

## 2. 기초 확인 순서

1. Unity Console의 **첫 번째 컴파일 오류**부터 해결한다. 뒤따르는 오류는 연쇄 결과일 수 있다.
2. 오류가 발생한 `.cs`가 어느 `.asmdef`에 속하는지 확인한다.
3. namespace 이름, `public/internal` 및 References를 검사한다.
4. 컴파일 성공 후 프리팹/씬의 Inspector 참조를 점검한다.
5. 이벤트 구독 시점·호출 여부를 로그 또는 디버거로 확인한다.
6. EditMode → PlayMode → 실제 씬 순서로 검증 범위를 넓힌다.

## 3. 어떤 기술을 선택할까?

| 내가 해결하려는 문제 | 우선 후보 | 피할 실수 |
| --- | --- | --- |
| 여러 적이 같은 공격 API에 응답 | Interface | 적 타입별 `if`만 계속 추가 |
| 한 메서드만 동적으로 전달 | Delegate (`Action`/`Func`) | 콜백을 public 필드로 무분별 공개 |
| 상태 변경을 여러 UI에 알림 | Event / Observer | 구독 해제 누락, 중복 구독 |
| 모듈 간 피해 데이터 교환 | DTO | 구현 클래스 전체를 전달 |
| 구현 객체를 선택해 연결 | DI | 숨겨진 전역 Service Locator |
| 기존 API와 새 API가 불일치 | Adapter | 기존 코드 전체를 무작정 재작성 |
| 복잡한 하위 시스템의 외부 API 단순화 | Facade | 모든 책임을 하나의 거대한 Manager에 몰기 |
| 어셈블리 간 타입 접근 제한 | `.asmdef` + `internal` | 서로 순환 참조하게 만듦 |
| Unity 설정 데이터를 에셋화 | ScriptableObject | 런타임 상태를 무계획 공유 |
| 필수 컴포넌트 자동 부착 | `[RequireComponent]` | 기존 프리팹도 자동 고쳐질 것으로 가정 |
| 코드 연결 실제 동작 검증 | Integration/PlayMode Test | 컴파일 통과만으로 종료 |
| 팀 기능을 안전하게 합치기 | 작은 PR + CI | 마지막 날 한꺼번에 병합 |

## 4. 기능 분담 전 기술 합의 체크리스트

- [ ] 기능의 입력과 출력이 정의되어 있다.
- [ ] 상태를 실제로 소유하는 모듈·클래스가 하나로 명확하다.
- [ ] 다른 팀이 호출할 인터페이스/메서드/이벤트가 정의되어 있다.
- [ ] DTO 데이터 형식과 의미, 단위, 유효 범위가 명확하다.
- [ ] 어떤 어셈블리가 어떤 모듈을 참조할지 정했다.
- [ ] 구현체가 완성되지 않아도 Fake/Stub으로 개발할 수 있다.
- [ ] Inspector·씬·프리팹 연결 담당자가 정해져 있다.
- [ ] 완료 조건과 최소 통합 테스트가 있다.

## 5. PR 생성 전 체크리스트

- [ ] 내 변경이 외부 공개 API를 바꿨는지 확인한다.
- [ ] Contracts 변경이 있다면 연관된 구현체 모두 영향 확인한다.
- [ ] 새 `static` 상태/이벤트가 필요했는지 근거를 설명한다.
- [ ] `Awake/OnEnable/Start/OnDisable`의 연결 시점이 맞는지 확인한다.
- [ ] asmdef References를 무조건 추가하지 않고 의존 방향을 검토한다.
- [ ] 테스트 결과와 수동 씬 확인 방법을 PR에 적는다.
- [ ] 씬·프리팹·`.meta` 파일이 필요에 맞게 포함되었는지 확인한다.

## 6. 용어를 마지막으로 구분

**변수**는 값을 담는 선언을 뜻하며, 더 정확히는 **지역 변수/매개변수/필드/속성**으로 구분한다. **static**은 타입에 속한다는 뜻이지 자동으로 글로벌이라는 뜻이 아니다. **interface**는 계약 타입이다. **delegate/event**는 메서드 호출과 알림의 통로다. **namespace**는 이름 공간이고 **asmdef**는 컴파일 단위와 어셈블리 참조 설정이다. **DI**는 실제 객체를 전달하는 기법이고 **Git merge**는 파일 변경 이력을 결합하는 작업이다.
